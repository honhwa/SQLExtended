## 修復：DAC 被佔用被當成永久失敗（Decryption）

**症狀**：`-- Procedure: [dbo].[wsp_QueryReport]` + "server's single dedicated administrator connection is already in use"。

**根因**（兩個，同一條錯誤分類）：
1. `UnavailableServers[server]` 把 transient 的 DAC busy 當永久事實快取 → session 內永不再試，只能 Clear All Cache。
2. `DacConnectionFactory.Explain` 用 `"dedicated administrator connection"` 全字比對，Azure 的 "not supported" 也被歸成 busy，並顯示「關掉別的 DAC session」這種無效建議。

**改動**：
- `SQLExtended/Decryption/DacConnectionFactory.cs`：新增 `internal static bool IsBusy(Exception)`（先看 `SqlException.Number == 17810`，再看文字；只認 "maximum number of" 或 "dedicated administrator"+"already exists"）；`DacUnavailableException` 加 `IsBusy` 屬性；`Explain` 改為 `internal` 且以 `IsBusy(ex)` 分流。
- `SQLExtended/Decryption/ModuleDecryptionService.cs`：新增 `OpenDac`，busy 時線性退避重試 3 次（750ms×1、×2，共 ~2.25s）；`catch (DacUnavailableException)` 只在 `!IsBusy` 時寫 `UnavailableServers`；busy 的最終訊息加 "(Tried 3 times; ...)" 說明與伺服器無關。
- `SQLExtended/Decryption/CLAUDE.md`：新增 bullet 記錄 busy vs 永久失敗的分界與 Azure 誤判。
- 新測試 `SQLExtended.Tests/Decryption/DacConnectionFactoryTests.cs`（7 個）。

**驗證**：主專案 build 0 error、0 `warning CS`；測試 1754 passed / 0 failed。
註：本機 `dotnet build` 需 `-p:NuGetPackageRoot='G:\nuget\packages\'`（環境變數缺結尾斜線，會讓 VSSDK targets import 失敗）；`CopyToSsms` 需提權，非提權時用 `-p:SsmsExtDir=<可寫目錄>` 繞過。

## 修復：csproj 無法載入（NuGetPackageRoot 缺結尾分隔符）

**症狀**：VS 報 `Project "G:\nuget\packagesmicrosoft.vssdk.buildtools\...\Microsoft.VsSDK.targets" was not imported ... file not existing`。

**根因**：`obj\SQLExtended.csproj.nuget.g.props` 在部分機器把 `NuGetPackageRoot` 寫成 `G:\nuget\packages`（無結尾 `\`），而 NuGet 自己生成的 import 全部寫成 `$(NuGetPackageRoot)\...`。`SQLExtended.csproj:366` 直接拼接 `$(NuGetPackageRoot)microsoft.vssdk...` → 路徑黏成一串。之前的 `-p:NuGetPackageRoot=...\` 只是繞過。

**改動**：csproj import 改為 `$([MSBuild]::EnsureTrailingSlash('$(NuGetPackageRoot)'))microsoft.vssdk...`，並加註解說明（含上面被註解掉的舊 import 有同樣 bug）。

**驗證**：不再需要任何 `-p:NuGetPackageRoot` 覆寫；`SQLExtended.slnx` build 0 error（72 條既有 MSB3277），測試 1754 passed。

## 修復：CopyToSsms 非提權時讓整個 build 失敗（MSB3191）

**症狀**：VS 報 `MSB3191 Unable to create directory ...\Extensions\SQLExtended. Access is denied`（Error 級）。

**根因**：`CopyToSsms` target（AfterTargets=Build）無條件 `MakeDir` + `Copy` 到 Program Files；非提權時直接把 build 打成 error，而編譯本身沒問題。同 target 內處理 `extensions.configurationchanged` 的 `Touch` 早就用 ContinueOnError + Warning 降級了，只有部署主體沒跟上。

**改動**（`SQLExtended/SQLExtended.csproj`）：拆成兩個 target
- `CopyToSsms`：只做可寫性探測 —— 一條 `Exec cmd /c if not exist ... mkdir ... & copy /y NUL <.deploy-probe>`，`IgnoreExitCode` + `Standard*Importance=low`（用 Exec 是為了不讓 MakeDir/WriteLinesToFile 先噴一條 MSB3191 警告蓋過真正的說明）；`Exists(.deploy-probe)` 決定 `_SsmsExtDirWritable`，成功則刪除探測檔，失敗則發一條說明性 Warning。
- `CopyToSsmsPayload`（AfterTargets=CopyToSsms，`Condition="'$(_SsmsExtDirWritable)' == 'true'"`）：原本所有 Copy + Touch 原封不動。

**驗證**：非提權 `-t:Rebuild` → Build succeeded，僅 1 條說明性警告（無 MSB3191）；`-p:SsmsExtDir=<可寫目錄>` → payload 正常部署、探測檔已刪；`SQLExtended.slnx` 0 error；測試 1754 passed。
