DataByte for SSMS 2026.10.15.1506

New
- Confirm before an UPDATE or DELETE without a WHERE clause. Executing a query (F5, Ctrl+E or the toolbar's Execute) first checks what is about to run — the selection, or the whole script when nothing is selected — and if any UPDATE or DELETE has no WHERE, lists each one with its line number and asks whether to go ahead. No is the default button, so an Enter pressed out of habit cancels. Not flagged: table variables and #temp tables, a table restricted by an INNER JOIN on it, WHERE CURRENT OF, and statements inside a CREATE or ALTER PROCEDURE, FUNCTION or TRIGGER. DELETE TOP (n) is still flagged, since in a loop it empties the table. A script that does not parse, including a SQLCMD-mode script, is run without the check. On by default; Settings → Editor → Execution safety.
- IntelliSense: an alias for every table picked after FROM or JOIN. Picking Company inserts `dbo.Company c`, and that table's columns are then offered as `c.ACTIVE` even when it is the only table in the query. The alias is the table's initials, numbered when it would clash with a table or alias already in the statement. It is only added where T-SQL allows one — not after INSERT INTO, UPDATE, DELETE FROM or TRUNCATE TABLE — and not when the name you are replacing already has an alias after it. Table-valued functions do not get one. On by default; Settings → IntelliSense, "Add an alias to tables picked after FROM / JOIN".
- IntelliSense: UPDATE template. After `UPDATE dbo.Company ` the list offers "(all columns) SET col = val": every column that can be set, each with a placeholder for its type, and a WHERE on the primary key. The key columns are left out of the SET, and so are identity, computed and rowversion columns. A table with no primary key gets `WHERE 1 = 0`, which updates nothing until you write a real condition. It follows the formatter's indent, comma position and keyword case, like the INSERT templates.
- Single quotes close themselves. Typing ' inserts '' with the cursor between them; typing ' again steps over the closing quote, and Backspace on an empty pair removes both. It stays out of the way inside strings (including ones that span lines), comments and bracketed or double-quoted names, and after a word, so O'Brien types normally — except the N of N'…'. On by default; Settings → IntelliSense → Typing, "Close single quotes automatically".

Changed
- Aliases in the foreign-key JOIN suggestions are no longer cut off at four letters: ORDER_LINE_ITEM_TAX_PAYMENT is now olitp rather than olit, so tables that share a prefix get different aliases.

Thanks to Mauricio Miglioranza, who contributed all of the above.
