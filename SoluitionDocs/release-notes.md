DataByte for SSMS 1.0.7

New
- Agent Jobs (Ctrl+Alt+J): a live SQL Server Agent job list for the current connection, showing what Object Explorer Details cannot — last run outcome with the failure message on hover, last and average duration (averaged over successful runs only), next scheduled run, the currently executing step and how long it has been running, owner, category, enabled state and the notification e-mail operator with when it fires. Report Server (SSRS subscription) jobs are hidden by default and the hidden category list is configurable. Filter by name, category or owner; select a job for its Steps and run History (loaded on demand). Right-click a job to Run Now, Stop, Enable or Disable it (each confirms first, naming the job and the server); needs SQLAgentOperatorRole or job ownership. Double-click a job (or press Enter, or right-click > Job Properties) to open SSMS's own Job Properties dialog, the same one Object Explorer opens, and the grid refreshes when you close it. Also available by right-clicking the Jobs folder or a job in Object Explorer. Needs SQLAgentReaderRole or sysadmin — the window says so when the login has neither and is therefore only seeing its own jobs.
- Performance Monitor (Ctrl+Alt+P): a live dashboard for the current connection. Vitals tiles with trend sparklines for CPU (SQL vs other), batch requests, active and blocked requests, page life expectancy and tempdb usage. Activity lists every running request plus idle sessions holding an open transaction, with wait type, wait time, CPU, reads, memory grant and statement text. Blocking shows the chains indented from each head blocker. Waits and File I/O report deltas over the sample window rather than totals since startup, with the usual benign waits filtered out (toggleable) and file latency flagged amber from 20 ms and red from 50 ms. Top queries ranks the plan cache by average or total CPU, duration, reads or execution count. Any tab's T-SQL, or a selected row's full statement, opens in a new query window.
- Performance Monitor: new Server info tab. What the instance says about itself in one place — name, edition, engine edition, collation, authentication mode, clustered and Always On state, uptime, the host's sockets, cores, NUMA nodes, memory and virtualisation type, the OS, the service account and its startup type, instant file initialization, tempdb's file layout, and the instance-level settings that matter (max server memory, MAXDOP, cost threshold for parallelism, max worker threads and the rest), with a setting that has been changed but not restarted into called out as such. Alongside it, the build is matched against the SQL Server build list: which release and servicing level it is, what has been released since, how many of those are cumulative updates, and where the release sits in its support lifecycle — in mainstream support, extended support (security fixes only), or out of support. Withdrawn and pre-release builds are flagged. The build list is an embedded snapshot rather than a live lookup, and the tab always names the snapshot date: a server newer than the snapshot is reported as "the list is out of date", never as up to date.
- Replication Monitor (Ctrl+Alt+R): a dockable window for replication on the current connection. Overview answers "is it working" in one line, with role cards for distributor, publications, subscriptions and worst latency. Subscriptions is the main grid: status, agent state, log reader and distribution latency and their end-to-end total with a trend sparkline, last activity, how much of the distribution retention window has been used up, delivered transactions and commands, and the agent job's enabled/running state. Publications shows type, articles, subscription count, retention and last snapshot outcome; Agents lists log reader, distribution, snapshot and merge agents together with their last error and merge conflict counts. Publisher reads the publisher itself, where a log held by REPLICATION and how full it is are visible — the failure that fills a disk and which the distribution database says nothing about — alongside sp_replcounters and each subscriber database's own record of its progress. Undelivered command counts, the MSrepl_errors list and tracer tokens load on demand rather than on the timer. Post a tracer token to measure end-to-end latency for real rather than by estimate (confirms first, naming the publication and the server; only from the publisher). Works from a publisher or a subscriber too — it collects what that connection can see and says what it cannot.
- Always On Monitor (Ctrl+Alt+A): a dockable window for the availability groups on the current connection. Overview cards per group with a "needs attention" list; per-replica role, connection, operational and synchronization health with the last connect error; per-database send/redo queue sizes and rates with inline trend sparklines, secondary lag, estimated data loss and recovery time, LSNs and suspend reasons; live automatic-seeding progress with percentage, transfer rate, ETA and network/disk waits, plus seeding attempt history; and recent AlwaysOn_health extended events on the Errors tab. Optional auto-refresh from 2s to 60s. Any tab's underlying T-SQL can be opened in a new query window.
- Always On Monitor: new Diagnostics, Throughput, Cluster and Listeners tabs. Diagnostics ranks what is actually wrong and says what to do about it, including the problems no single grid shows — an automatic-failover pair that could not fail over right now, or a group below its required synchronized secondary count, where every replica reads HEALTHY while the primary refuses commits. Throughput reports what synchronous commit is costing the primary in milliseconds per transaction, plus log received/redone rates and the transport's flow control and resent messages. Cluster shows quorum type and state and each member's vote count, plus each replica's cluster join state. Listeners shows every listener IP and whether it is online — a client-facing outage that leaves every replica reporting healthy — with the read-only routing lists and the routing URLs that make read-intent routing work or silently do nothing. Replica rows gained session timeout and both routing URLs; database rows gained a joined column. Thresholds for all of it are configurable under DataByte Settings > Monitoring.
- Parse Statistics (Ctrl+K, Ctrl+G): parses the active query window's STATISTICS IO/TIME output into sortable per-statement tables with % logical reads, per-table totals and grand totals, in a new dockable Statistics window. Copy the report as tab-separated text for Excel. Parser vendored from Brent Ozar Unlimited's MIT-licensed Statistics Parser extension — see third-party-notices.md.
- Export schema to a folder: in the Schema Cache window, right-click a database (or use the Export button) to script it out as one .sql file per object, in a subfolder per object type — Tables, Views, Stored Procedures, Functions, Table Types, User-Defined Types, Sequences, Synonyms, Schemas, Database Triggers. Tables carry their indexes, keys, checks, defaults and triggers. Built for folder-compare tools like WinMerge: nothing volatile is written (no export timestamps, no row counts), so a file differs only when the object does, and a single database always lands at the same relative paths on both sides. Right-click a server to export every cached database at once, into a folder per database. Re-exporting offers to clear the previous scripts first, so objects dropped since the last export don't linger and misreport the next diff.
- Decrypt encrypted modules: recovers the text of procedures, views, functions and triggers created WITH ENCRYPTION, so their bodies show up in the schema viewer (Ctrl+Shift+D), in SQL Search's "search in definitions", and in both schema exports instead of appearing blank. (Completion lists and column suggestions were never affected — encryption hides a module's body, not its columns or parameters.) Off by default and switched on under DataByte Settings > Schema Cache: there is no key to decrypt with, so recovering the text means briefly ALTERing each object to a throwaway definition over a dedicated administrator connection and rolling that back in the same batch — nothing is ever left changed, but it takes a schema-modification lock, recompiles the module, and needs sysadmin. Each object is decrypted once per version rather than on every cache refresh. Anything that cannot be recovered is named and skipped: a folder export writes no file for it rather than SMO's "not transferable" placeholder, which is identical for every encrypted object and would make two servers' differing procedures compare equal.
- Script Results as INSERT: right-click a results grid to generate a temp-table CREATE + INSERT script in a new query window. The DataByte menu version scripts every grid in the active window.
- Stored procedure parameter expansion: accepting an EXEC completion inserts an "@param = value -- type" line per parameter with Tab stops between the values (SQL Prompt style). Can be turned off in DataByte Settings.
- Import Red Gate SQL Prompt snippets into the DataByte snippet library.
- Object Explorer: connected servers are grouped into folders mirroring your Registered Servers groups, with a "Regroup Servers Now" command. Configurable in DataByte Settings.
- New formatting options: stacked SELECT column layouts, stacked CTE layout, normalize JOIN keywords (LEFT OUTER JOIN -> LEFT JOIN), leading-comma indentation, and WHERE AND/OR alignment.
- Formatting option: stacked derived table layout (Layout > Derived Tables). A subquery in FROM, JOIN or APPLY is reflowed the same way the stacked CTE layout reflows a CTE — the opening bracket ends the JOIN line, the body sits one level in and is formatted like any other query, and the closing bracket comes back to the margin alongside the alias and its ON. ScriptDom otherwise aligns the body under whatever column the bracket happened to land in, which is a different column for every join in the statement. Nested subqueries stack at their own level; anything that is not a table reference (IN, EXISTS, a scalar subquery in the SELECT list) is left alone.
- More formatting options: built-in function names are now cased like keywords, so `row_number()`, `sum()`, `getdate()` and the rest come back as `ROW_NUMBER()`, `SUM()`, `GETDATE()` (General > Built-in function case; upper by default, and it only touches names in call position, so a column called `Count` or a `dbo.Count()` of your own is left alone). "Opening ( on the table line" keeps an INSERT's bracket with the table — `INSERT INTO #tt (` — with the columns stacked beneath it. Leading commas now reach the INSERT column and VALUES lists and procedure parameter lists, which were still coming out with trailing commas whatever the comma setting said. "SET left-aligned with UPDATE" puts SET at the UPDATE's own indent with the first assignment on the same line and the rest one level in.

Fixed
- Formatter: a JOIN to a subquery kept its ON on a line of its own even with "ON on same line as JOIN" set, and — worse — the subquery's own FROM became the alignment target for the outer query, so every join below it was indented to wherever that inner FROM happened to land. Both are fixed, and a subquery's own joins now align to its own FROM instead of being left where they fell.
- Cross-database IntelliSense: columns are now suggested for database-qualified tables (e.g. [OtherDb].dbo.Table) in SELECT, WHERE, JOIN ON, star expansion, and INSERT templates. Referenced databases are cached automatically on first use.
- Search and History windows failed to open when Red Gate SQL Prompt was also installed. A clear error message (with ActivityLog details) now appears if a window still can't open.
- Snippet placeholders ($dbname$, $server$) now resolve reliably when completion runs in the background.
- Database/connection switches are now detected while a query window is open, keeping the schema cache and snippet placeholders current.
